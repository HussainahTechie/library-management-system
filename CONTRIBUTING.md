# Contributing

Thank you for your interest in improving the Library Management System!

## Reporting a bug
Open a new issue using the **Bug report** template. Include the steps to
reproduce it, what you expected, and what happened.

## Suggesting a feature
Open an issue using the **Feature request** template and describe the problem
it would solve.

## Submitting code
1. Fork the repository (or, if you are a team member, clone it).
2. Create a branch: `git checkout -b feature/short-description`
3. Make your changes and add tests where possible.
4. Run `pytest` and make sure everything passes.
5. Commit with a clear message, e.g. `Add search by author to books.py`.
6. Push your branch and open a Pull Request that mentions the issue
   (e.g. `Closes #7`).
7. Wait for a review. At least one other person must approve before merging.

## Rules
- Never push directly to `main`.
- Keep pull requests small and focused.
- Follow PEP 8 style and add docstrings to new functions.
- Be respectful and kind to everyone.

## Good first issues
Look for the **good first issue** label, for example: export books to CSV,
calculate late fees, or add a "list borrowed books" option.
